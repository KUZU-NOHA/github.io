# ドローンショー デザイナー

3D で隊列とアニメーションを設計し、各機の飛行経路（時刻・XYZ座標・LED色）を CSV / JSON に書き出すツール。
[ドローンショー実施プログラム 要件定義書](../../docs/drone-show-requirements.md) の
§5.1 振り付け設計 / §5.2 シミュレーション・安全検証 / §5.3 ミッション生成 に対応する。

**公開先**: <https://kuzu-noha.github.io/app/drone-show/>

> このツールが担うのは設計〜検証〜データ書き出しまで。実機への配信・監視・緊急停止は範囲外で、
> 出力ファイルを地上局ソフト（Skybrush Server / ArduPilot 系）に取り込んで使う想定。

## 使い方

1. **左ペイン**でショー全体（機数・安全上限）を設定する
2. **キーフレーム**を並べる。1 キーフレーム = 1 隊列で、その並びがそのまま時間軸になる
   （静止 → 遷移 → 静止 → …）
3. **中央の 3D ビュー**で再生・確認する
   - ドラッグ = 回転 / Shift+ドラッグ・右ドラッグ = 平行移動 / ホイール = ズーム
4. **安全検証**を実行する
5. 合格したら **CSV / JSON を書き出す**

## 設計上のポイント

### 機体の割当は自動（ハンガリアン法）

隊列 A から隊列 B へ移るとき、「どの機体がどの位置へ向かうか」を順番どおりに決めると軌道が
交差して衝突リスクが跳ね上がる。本ツールは総移動距離（二乗和）が最小になる 1 対 1 対応を
ハンガリアン法 O(n³) で解いている（機体 300 機超では貪欲法にフォールバック）。

### 曲線隊列は弧長で等間隔

ハートや渦巻きを媒介変数のまま等間隔に取ると、曲線の進みが遅い箇所（ハート下端の尖点など）に
機体が密集する。実装では曲線を細かくサンプリングしてから**弧長**で取り直しており、
どの隊列でも機体間隔がほぼ均一になる。

### テキストは「機体間隔」が基準

`1マス [m]` は隣り合う機体の間隔。機数が多くてビットマップのセル数を超える場合、セルを細分すると
同時に文字全体を物理的に拡大するため、機数を増やしても安全距離を割らない。英数字と記号のみ対応。

### 遷移カーブ

`スムーズ`（既定）は始終端で速度 0 になる。ピーク速度は `1.5 × 移動距離 ÷ 秒数`、
ピーク加速度は `6 × 移動距離 ÷ 秒数²` になるので、検証に落ちたらまず遷移秒数を伸ばす。
`等速` は端点で加速度が無限大になるため実機では非推奨。

## 安全検証の項目

| 項目 | 内容 |
|---|---|
| 機体間距離 | 全機体ペア × 全時刻の最小距離が基準以上か |
| 最大速度 / 最大加速度 | 機体スペックの範囲に収まっているか |
| 最高高度 | 上限（航空法の 150 m 未満に余裕を見た値）以内か |
| 地表クリアランス | 飛行中（離着陸区間を除く）に下限を割っていないか |
| 水平ジオフェンス | 原点からの水平距離が上限以内か |
| 飛行時間 / バッテリ | ショー長がバッテリ想定内か |

検証に不合格でも書き出しは可能だが、**実機へのアップロードは禁止**。
出力ファイルの `meta.validation` に検証結果が記録される。

## 出力フォーマット

座標系は **ENU（x = 東, y = 北, z = 高度）**、単位はメートル、原点は離陸グリッドの中心。

### 軌道 CSV（`*_trajectory.csv`）

```csv
drone_id,time_s,x_m,y_m,z_m,r,g,b
1,0,-18,8,0,255,255,255
1,0.1,-18,8,0,255,255,255
```

### 軌道 JSON（`*_trajectory.json`）

サンプルは `[t, x, y, z, r, g, b]` の配列。

```json
{
  "format": "drone-show-trajectory",
  "version": 1,
  "meta": {
    "drone_count": 50,
    "duration_s": 122,
    "fps": 10,
    "coordinate_system": "ENU (x=east, y=north, z=up), origin = launch grid center",
    "units": { "position": "meter", "time": "second", "color": "sRGB 0-255" },
    "limits": { "safetyDistance": 2.5, "maxSpeed": 6, "...": "..." },
    "validation": { "passed": true, "min_separation_m": 2.63, "checks": [] }
  },
  "sample_fields": ["t_s", "x_m", "y_m", "z_m", "r", "g", "b"],
  "drones": [{ "id": 1, "samples": [[0, -18, 8, 0, 255, 255, 255]] }]
}
```

### 離陸配置 CSV（`*_launch_positions.csv`）

現地で機体を並べるための配置表。`drone_id,x_m,y_m,z_m`。

### プロジェクト JSON（`*_project.json`）

キーフレーム定義そのもの。「プロジェクト読込」で再編集できる。

## 実装

ビルド不要の静的サイト（Vanilla JS + ES Modules）。**外部ライブラリを一切使わない**ため、
オフラインでも CDN 障害時でも動く。3D 表示は Canvas 2D の自前レンダラ
（点の投影と奥行きソートだけで夜空の光点は十分再現できる）。

| ファイル | 役割 |
|---|---|
| `js/formations.js` | 隊列ジェネレータ 13 種。必ずちょうど n 点を返す |
| `js/font5x7.js` | テキスト隊列用の 5×7 ビットマップフォント |
| `js/assign.js` | ハンガリアン法による機体割当 |
| `js/show.js` | データモデル・タイムライン・軌道サンプリング |
| `js/validate.js` | 安全検証 7 項目 |
| `js/exporters.js` | CSV / JSON 書き出しと読み込み |
| `js/viewer.js` | Canvas 2D の 3D レンダラとカメラ操作 |
| `js/main.js` | 状態管理と UI 配線 |

### ローカルで動かす

ES Modules を使うため `file://` では動かない。静的サーバー経由で開くこと。

```sh
python3 -m http.server 8000
# → http://localhost:8000/app/drone-show/
```
