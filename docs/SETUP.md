## STEP 3 — スマートトレーナーを繋ぐ

### 3-1. 事前準備（つまずきやすい点）

| 確認 | 内容 |
|---|---|
| **他アプリを終了する** | Zwift・Rouvy・TrainerRoad 等が繋がっていると接続できません。BLE トレーナーは**同時に1台としか繋がらない**のが普通です。スマホのアプリも終了してください |
| **トレーナーを起こす** | 電源を入れ、**ペダルを数回転させる**。多くのトレーナーは動かさないとスリープしていて、Bluetooth の一覧に出てきません |
| **PC の Bluetooth を ON に** | Windows：設定 → Bluetooth とデバイス<br>Mac：システム設定 → Bluetooth |
| **Mac は Chrome に権限を** | システム設定 → プライバシーとセキュリティ → **Bluetooth** → **Google Chrome** を ON |

### 3-2. 接続する

1. 走行画面の右側 **「バイクに接続」** をクリック
2. Chrome のデバイス選択ダイアログが開く
3. 一覧からバイクを選び **「ペア設定」** をクリック
4. 「○○ に接続しました」と出れば成功

> **心拍計として繋がるバイクについて**
> 一体型エアロバイクには、FTMS を広告せず**心拍サービスだけを広告する**機種があります。
> 「心拍計に接続」では出てくるのに「バイクに接続」で出てこない場合がこれです。
> 現在は心拍サービスも検索対象に含めているため、**「バイクに接続」で出てくるはずです。**
> 接続してから中身（FTMS / Cycling Power / CSC）を調べる方式なので、
> 広告に載っていないサービスも拾えます。

#### 一覧に出てこないときは「全デバイスから選ぶ」

**一体型のエアロバイク（バイク本体にセンサーが全部入っているタイプ）は、
「バイクに接続」で出てこないことがあります。** Bluetooth の広告パケットに
サービス情報を載せていない機種があるためです。

その場合は **「見つからない場合：全デバイスから選ぶ」** をクリックしてください。
周囲の Bluetooth デバイスがすべて表示されるので、そこからバイクの名前を選びます。
接続してから中身を調べる方式なので、広告に情報が無い機種でも繋がります。

> 一覧が長い場合は、バイクの電源を入れ直すと名前が分かりやすく出ることがあります。
> 型番や「BIKE」「FIT」などを含む名前を探してください。

#### 接続後の表示で対応状況が分かります

デバイス欄に、どのサービスで繋がり何が取れているかが表示されます。

```
FTMS で接続 / 取得: パワー・ケイデンス・速度 / 勾配連動に対応
Cycling Power で接続 / 取得: パワー・ケイデンス・速度(パワーから算出) / 勾配連動は非対応
CSC で接続 / 取得: ケイデンス・速度 / 勾配連動は非対応
```

| 表示 | 意味 |
|---|---|
| **FTMS** | 最も情報量が多い。勾配連動も使える可能性が高い |
| **Cycling Power** | パワーが取れる。消費カロリーは実測ベースになる |
| **CSC** | 速度・ケイデンス。カロリーは METs 推定になる |
| **速度(パワーから算出)** | バイクが速度を出さない機種。パワーと勾配から物理計算で速度を求めています。坂では自然に遅くなります |
| **勾配連動に対応（FTMS）** | 標準プロトコルで負荷を制御します |
| **勾配連動に対応（Wahoo 独自プロトコル・実験的）** | 下記参照 |
| **勾配連動は非対応** | 走行はできますが負荷は変わりません |

複数のサービスは**併用されます**。たとえば「Cycling Power からパワー、
CSC から速度・ケイデンス」のように分かれている機種でも、両方を使って統合します。

#### 動作確認済みの機種

| 機種 | 構成 | 状態 |
|---|---|---|
| **HITFIT_19403** | Cycling Power + CSC + Heart Rate + Wahoo 独自制御 | パワー・速度・ケイデンス・心拍が取得可能。勾配連動は実験的対応 |

### 3-3b. 勾配連動について（Wahoo 独自プロトコル）

FTMS を持たない機種でも、Cycling Power サービス配下に
`a026e005-0a7d-4ab3-97fa-f1500f9feb8b` という特性があれば勾配連動が使えます。
これは Wahoo が自社トレーナー用に使っているプロトコルで、
他社製バイクにも採用例があります。

**⚠️ このプロトコルは非公開です。** バイト仕様はコミュニティの参照実装
（kinetic-fit/sensors-swift-trainers 等）に基づいており、Wahoo 以外の機種では
同じ UUID でも解釈が違う、あるいは一部しか実装されていない可能性があります。

そのため本アプリでは:

- 全ての書き込みを失敗許容にしています（効かなくても走行は止まりません）
- 勾配は **±25% に丸めて**送ります。想定外の値で負荷が跳ね上がるのを防ぐためです

**坂道でペダルの重さが変わるかどうか、実際に試して教えてください。**
変化しない場合は設定画面で「勾配連動を使う」をオフにしてください
（走行自体には影響しません）。

#### 勾配連動を精緻化しました

坂道の負荷計算を、以下の3点で実走に近づけています。

- **標高データのノイズ除去**: Elevation API・GPX の標高には数十cm〜数m単位の
  ばらつきがあり、そのまま使うと平坦な道でも負荷が細かくガタつきます。移動平均で
  ならしてから使うようにしました
- **勾配変化の急な飛びを抑制**: 1秒あたりの変化を最大6%までに制限しています。
  実際の坂の入り口・出口では自然に反映されつつ、データのノイズだけで
  負荷が跳ねることを防ぎます
- **選んだ車種の反映**: 設定画面の「車種」（TT／ロード／クロス／シティ）に応じて、
  転がり抵抗・空気抵抗の設定値をトレーナーに送るようにしました。
  以前は車種を変えても表示速度にしか反映されず、坂道の負荷計算は
  常に同じ設定値のままでした

体感として「坂道の重さが自然になった」「車種を変えると坂の効き方も変わる」かを
確認していただけると助かります。

### 3-3. 走る

**「走行開始」** を押してペダルを回してください。実際の速度で景色が進みます。

### 3-4. 繋がらないときは

| 症状 | 原因と対処 |
|---|---|
| **「バイクに接続」で何も出ない** | **「全デバイスから選ぶ」を試してください。**一体型エアロバイクではこちらでないと出てこないことがあります |
| 「全デバイスから選ぶ」でも出ない | バイクがスリープ中 → ペダルを回してから再試行。他アプリが掴んでいる → 全部終了 |
| 「対応するサービスが見つかりませんでした」 | 選んだデバイスが FTMS / Cycling Power / CSC のどれも持っていない。別のデバイスを選ぶか、メーカー独自プロトコルのみの機種の可能性 |
| 「Web Bluetooth に非対応」と出る | Safari・Firefox・iOS を使っている → **PC/Mac の Chrome** で開く |
| 繋がるが数値が 0 のまま | ペダルを回してください。CSC のみの機種は回し始めてから数秒かかります |
| 速度だけ 0 のまま | 速度を出さない機種です。パワーが取れていれば自動で算出します。表示が「取得: パワー…」だけなら、パワーも来ていない可能性 |
| **速度が異常な値になる／大きく暴れる** | 設定画面の **「速度の求め方」→「パワーから算出」** にしてください。詳細は下記 |
| 走行中に切れる | 電波干渉。バイクと PC を近づける。USB3.0 機器（2.4GHz に干渉）を離す |

### 3-3c. 速度が異常な値になる・大きく暴れる場合

**設定画面の「速度の求め方」を「パワーから算出」に変えてください。** これで解決します。

#### なぜ起きるのか

一体型エアロバイクが CSC で返す「ホイール回転数」は、**実際の車輪の回転ではなく
内部のカウント**であることがほとんどです（そもそも車輪がありません）。
これにホイール周長を掛けても意味のある速度にはならず、
機種によっては桁違いの値になります。

加えて、通知の間隔が短いと「2回分の差分」で計算した瞬間速度は大きく跳ねます。
回転が1回でも間隔が 0.01 秒なら、計算上は毎秒100回転になってしまうためです。

#### アプリ側でも3段階の対策を入れています

| 対策 | 内容 |
|---|---|
| 測定窓の確保 | 0.5秒ぶんの回転がたまるまで計算しない |
| 妥当性チェック | 100km/h 超・250rpm 超はノイズとして捨てる |
| 変化率の制限 | 1秒あたり 10km/h を超える変化を許さない（実走の加速は速くても毎秒7km/h程度） |

それでも「内部カウント × ホイール周長」という前提自体が合っていないため、
**パワーが取れる機種ではパワーからの算出をおすすめします。**

#### 「速度の求め方」の選択肢

| 設定 | 動作 | 向いているケース |
|---|---|---|
| **自動（推奨）** | FTMS の速度 → パワーから算出 → センサー値、の順で使う | 通常はこれ |
| **パワーから算出** | 常にパワーと勾配から物理計算する | **一体型エアロバイクはこれが最適**。滑らかで、坂では自然に遅くなる |
| **センサーの値をそのまま** | センサーの速度を使う | 実車＋速度センサーの構成 |

「センサーの値をそのまま」を選ぶ場合は、**ホイール周長**の設定も実測値に
合わせてください（例: 700x25C = 2105mm）。

### 3-3d. もっと速く走りたい

方法が2つあります。設定画面で変更でき、**走行中でも即座に反映**されます。

#### ① 車種を変える（実走と同じ物理）

空気抵抗と転がり抵抗が変わり、**同じ出力でも到達速度が変わります。**
実走のロードバイク研究で使われる代表値を採用しています。

| 車種 | 75W | 100W | 150W | 200W |
|---|---|---|---|---|
| **TTバイク（最速）** | 25.6 | 28.8 | **33.7** | 37.6 |
| ロードバイク（既定） | 22.8 | 25.8 | 30.3 | 33.9 |
| クロスバイク | 20.9 | 23.6 | 27.9 | 31.2 |
| シティサイクル | 18.2 | 20.7 | 24.6 | 27.6 |

※ 総重量80kg・平地での速度[km/h]

ロード → TT で**約12%速く**なります。「速く走りたい」だけならまず車種を変えるのが自然です。

#### ② 速度の倍率を上げる（1.0〜5.0）

表示速度も景色の進みもそのまま倍になります。実走の物理からは外れますが、
**短時間でも「遠くまで行った感」が出る**ので、続けるモチベーションには効きます。

倍率を使っている間は、速度計の横に `×1.5 (実測 22.0)` のように
**実測値も併記**されるので、本当の出力を見失いません。

> **どちらを使うか**
> 「実走に近い感覚がほしい」なら車種を変える。
> 「とにかく景色をどんどん進めたい」なら倍率を上げる。
> 併用もできます（TTバイク × 倍率2.0 で 150W → 表示67km/h）。
>
> なお**消費カロリーはパワーから計算しているので、どちらを変えても影響しません**。
> ダイエットの記録は正確なまま、体感だけを調整できます。

#### 速度が体感より遅い場合

設定の**体重**が実際の値になっているか確認してください。物理計算に使っており、
軽いほど（特に坂道で）速くなります。

### 3-4b. 「デバイスを診断」で中身を調べる

繋がるのにデータが来ない、あるいは何のサービスも見つからないと言われる場合は、
デバイス欄の下にある **「デバイスを診断」** を押してください。

そのバイクが実際にどのサービスと特性を持っているかを調べて、こう表示します。

```
デバイス名: XXXX-BIKE

■ Cycling Power（パワー）
  00001818-0000-1000-8000-00805f9b34fb
   - 0x2A63 [notify]
   - 0x2A65 [read]

■ Heart Rate（心拍）
  0000180d-0000-1000-8000-00805f9b34fb
   - 0x2A37 [notify]
```

**「この結果をコピー」**でクリップボードにコピーできます。これを共有していただければ、
その機種に合わせた対応を判断できます。

> **診断の限界について**：Web Bluetooth の仕様上、あらかじめ列挙した UUID しか
> 調べられません（「全サービスを列挙する」ことは原理的にできない仕様です）。
> 標準サービスと主要メーカーの独自サービスは網羅していますが、
> 「既知のサービスは見つかりませんでした」と出た場合は、
> 完全に独自のプロトコルを使う機種ということになります。

**繋がらない場合に教えていただきたいこと**：バイクの機種名、診断結果、
**F12 → Console** に出ているメッセージ。対応を検討します。

## STEP 4 — API キーを取って 3D 映像を出す

ここまでは 2D 表示です。フォトリアルな 3D 映像を出すには Google の API キーが要ります。

> **費用について**：クレジットカードの登録が必要ですが、3D タイルは月1,000セッションが
> 無料枠で、**1回のライド＝1セッション**です。毎日乗っても無料枠に収まります。
> それでも念のため、4-4 の上限設定を必ず行ってください。

### 4-1. プロジェクトを作り、課金を有効にする

1. **https://console.cloud.google.com/** を開く（Google アカウントでログイン）
2. 画面上部のプロジェクト選択 → **新しいプロジェクト** → 名前を入れて **作成**
   （例: `virtual-cycling`）
3. 左メニュー **お支払い** → **請求先アカウントをリンク**
   → 無い場合は作成（クレジットカード登録が必要）

### 4-2. 5つの API を有効化する

左メニュー **API とサービス** → **ライブラリ** で、以下を1つずつ検索して
**「有効にする」** を押します。

| API 名 | 用途 |
|---|---|
| **Maps JavaScript API** | 3D 表示・ストリートビュー |
| **Map Tiles API** | フォトリアル 3D タイル（映像の本体） |
| **Routes API** | 地点指定でのルート生成 |
| **Elevation API** | 標高・勾配 |
| **Maps Static API** | 3D が使えない場合の背景地図（2Dフォールバック用） |

**5つとも必要です。**1つでも抜けると 3D が出ない、勾配が効かない、
3D 失敗時に地図が真っ白になる等が起きます。

### 4-3. キーを作る

1. **API とサービス** → **認証情報**
2. 上部 **＋ 認証情報を作成** → **API キー**
3. 表示された `AIza...` で始まる文字列を**コピー**（後で使います）

### 4-4. キーに制限をかける（⚠️ 必ずやってください）

キーはブラウザから見える状態になるため、制限しないと第三者に使われて
**高額請求が発生しえます。**

作成直後のダイアログ、または認証情報一覧からキー名をクリックして編集画面へ。

**① アプリケーションの制限**

- **ウェブサイト** を選択
- **「ウェブサイトの制限」→ 追加** で以下を入力：
  ```
  https://kuzu-noha.github.io/github.io/*
  ```
- STEP 5（手元の PC で動かす）も使うなら、これも追加：
  ```
  http://localhost:8000/*
  ```

**② API の制限**

- **キーを制限** を選択
- プルダウンから 4-2 で有効化した **5つの API だけ**にチェック

→ **保存**

**③ 1日の上限を決める**

**API とサービス** → 各 API を選択 → **割り当てとシステム上限** タブ
→ 1日あたりのリクエスト数に上限を設定します。

目安（毎日1回30分乗る想定の2〜3倍）：

| API | 1日の上限の目安 |
|---|---|
| Map Tiles API | 50 |
| Maps JavaScript API | 100 |
| Routes API | 50 |
| Elevation API | 50 |
| Maps Static API | 20（ルート選択のたびに1枚取得するため） |

**④ 予算アラート**

左メニュー **お支払い** → **予算とアラート** → **予算を作成**
→ 金額を 1,000円 などに設定し、50% / 90% / 100% で通知が来るようにします。

これが**最後の安全網**です。設定してください。

### 4-5. アプリにキーを入れる

1. アプリを開く：`https://kuzu-noha.github.io/github.io/app/`
2. 右上 **「設定」**
3. API キーの欄にコピーした `AIza...` を貼り付けて **「保存」**
4. **「✅ Google Maps 読み込み済み（3D 映像が使えます）」** と出れば成功

キーは**この端末のブラウザにのみ保存**され、リポジトリにもサーバーにも送信されません。
別の PC で使うときは、その PC でも同じ手順が必要です。

### 4-6. 3D で走る

ルートを選び直して走行を開始すると、フォトリアルな 3D 映像になります。

- **「見回す（ストリートビュー）」** ボタンで、その場の実写を確認できます
- 1km ごとに自動でストリートビューが数秒表示されます
- 設定画面の **カメラ距離 / カメラ俯角** で視点を調整できます
  （地上に近づけるほど 3D タイルの粗さが目立つので、初期値の 50m / 74度 を推奨）

### 4-7. うまくいかないときは

| 症状 | 対処 |
|---|---|
| 「Google Maps の読み込みに失敗」 | 4-2 の API が有効化されていない。特に **Map Tiles API** の抜けが多いです |
| 3D にならず 2D のまま | 同上。または課金が有効になっていない |
| 画面が真っ暗 | その地域が 3D タイル非対応。プリセットの「ゴールデンゲートブリッジ」で試すと切り分けできます |
| `RefererNotAllowedMapError` | 4-4 ① のウェブサイト制限が URL と一致していない。末尾の `/*` を確認 |
| 勾配が常に 0.0% | Elevation API が未有効。または GPX に標高が無い |
| 2D フォールバック時、背景が地図でなく無地のまま | **Maps Static API** が未有効。または F12 → Console で `staticmap` 関連のエラーを確認してください |

エラーの詳細は **F12 → Console** に出ます。内容を教えていただければ切り分けます。

## お気に入りルートとゴースト走行

### ルートを保存する

ルート選択画面でルートを選ぶと、「選択中のルート」カードに
**「☆ お気に入りに保存」** ボタンが出ます。押すと名前を入力する欄が開くので、
保存すると「お気に入り」セクションの一番上に表示されるようになります。

### ゴースト走行

**お気に入りに保存したルートを2回目以降走ると、自動的に前回のタイムと比較されます。**

- 走行開始時に「前回のタイム（○○）と比較します」と表示される
- 走行中は HUD に **「前回比 −00:15」** のように、前回より進んでいるか遅れているかが出る
  （マイナス＝前回より速い、プラス＝前回より遅い）
- 何回も同じルートを保存し直す必要はなく、**その中で一番速かった記録**が自動でゴーストになる
- 走行完了サマリーにも「前回より○○速く走れました」と表示される

特別な設定は不要です。同じお気に入りルートを選ぶだけで動きます。
プリセットルートや検索・GPXで作った一時的なルートでは、お気に入りに保存しない限り
ゴースト走行は有効になりません（同じルートかどうかを判定する基準が無いため）。

> 周回ルート（設定の「終点で最初に戻る」がオンのもの）はゴースト走行の対象外です。
> 距離が周回のたびに巻き戻るため、正しい比較ができません。

## ダイエット機能の使い方

### 走行完了サマリー

走行を終了すると、その場で成果画面が出ます。距離・時間・消費カロリーに加えて、
**心拍ゾーンの滞在時間**（心拍計を接続していれば）と、今週の目標までの残り、
連続日数が表示されます。「閉じる」で記録画面に移ります。

### 心拍ゾーン（記録画面）

直近7日間のゾーン滞在時間を帯グラフで見られます。
**Z2（脂肪燃焼ゾーン）** は脂肪がエネルギーとして使われる割合が最も高い領域で、
ダイエット目的ではここの滞在時間が重要です。心拍計を接続して走ると記録されます。

### 目標体重の達成予測

体重を4回以上・7日以上の間隔で記録すると、今のペースでの達成予測日が出ます。
日々の変動に惑わされないよう回帰直線で計算しており、目標に近づいていない場合は
（増加傾向など）その旨を正直に表示します。

### CSV / JSON エクスポート

記録画面の「データ管理」から、走行記録を CSV（Excel やスプレッドシートで開けます）
または JSON（体重記録を含む完全なバックアップ）で書き出せます。

## 補足 — iPhone で使いたい場合

iOS の Safari も iOS 版 Chrome も Web Bluetooth に対応していないため、
**そのままでは Bluetooth が使えません**（画面の表示や記録の閲覧はできます）。

使う場合は App Store の **WebBLE**（有料・数百円）というブラウザをインストールし、
その中で `https://kuzu-noha.github.io/github.io/app/` を開いてください。
WebBLE は iOS の CoreBluetooth を Web Bluetooth API に橋渡しする専用ブラウザです。

ただし WebBLE は Web Bluetooth API の一部しか実装していないため、
**実機で確認するまで動くとは断言できません**。まず PC/Mac で動かして、
そのあと WebBLE を試すのが確実です。
