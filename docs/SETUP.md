# 動かす手順（完全版）

このドキュメントの通りに進めれば動きます。**STEP 1 と 2 だけなら5分・費用ゼロ**で、
機材も API キーも無しに動作を確認できます。

| STEP | 内容 | 所要 | 費用 |
|---|---|---|---|
| 1 | GitHub Pages を有効化する | 3分 | 無料 |
| 2 | シミュレーターで動作確認する | 2分 | 無料 |
| 3 | スマートトレーナーを繋ぐ | 5分 | — |
| 4 | API キーを取って 3D 映像を出す | 20分 | 無料枠内 |
| 5 | （任意）手元の PC で動かす | 5分 | 無料 |

## STEP 1 — GitHub Pages を有効化する

### 1-1. 設定画面を開く

ブラウザで開く → **https://github.com/KUZU-NOHA/github.io/settings/pages**

### 1-2. 公開元のブランチを指定する

**Build and deployment** の欄で以下を設定します。

| 項目 | 選ぶもの |
|---|---|
| Source | **Deploy from a branch** |
| Branch | **`claude/google-maps-virtual-cycling-txcloc`** |
| フォルダ | **`/ (root)`** |

→ **Save** をクリック。

> ブランチのプルダウンに `claude/google-maps-virtual-cycling-txcloc` が出ない場合は、
> ページを再読み込みしてください。

### 1-3. 公開されるまで待つ

1〜3分かかります。進行状況は **Actions** タブ
（https://github.com/KUZU-NOHA/github.io/actions）で確認できます。
緑のチェックが付けば完了です。

### 1-4. URL を確認する

公開先はここです。

```
https://kuzu-noha.github.io/github.io/
```

> **⚠️ URL にご注意ください。**
> このリポジトリの名前は `github.io` であって `kuzu-noha.github.io` ではないため、
> **プロジェクトサイト**扱いになり、URL にリポジトリ名 `/github.io/` が入ります。
> `https://kuzu-noha.github.io/` （リポジトリ名なし）ではありません。

## STEP 2 — シミュレーターで動作確認する（機材・キー不要）

**PC / Mac の Google Chrome** で開いてください。

### 2-1. アプリを開く

```
https://kuzu-noha.github.io/github.io/app/
```

### 2-2. 操作手順

1. 設定画面が出るので **「キー無しで試す」** をクリック
   → 2D 表示モードで動きます。3D 映像は STEP 4 で有効になります
2. ルート画面で **「皇居一周」** をクリック
3. 画面下に「選択中のルート 3.88 km」が出たら **「走行画面へ →」**
4. 右側の **「シミュレーターで開始」** をクリック
5. **「走行開始」** をクリック

### 2-3. 確認できること

- 速度・パワー・ケイデンス・心拍の数値が動く
- 距離と時間が増える
- オレンジの点がルート上を進む
- 消費カロリーが積算される（「実測ベース ○ kJ」と表示される）
- 「一時停止」で止まり、もう一度押すと再開する
- 「終了して記録」で記録画面へ移り、履歴に残る

擬似出力のスライダーを動かすと速度が変わります。

**ここまで動けば、アプリの中身は正常です。**

## STEP 3 — スマートトレーナーを繋ぐ

### 3-1. 事前準備（つまずきやすい点）

| 確認 | 内容 |
|---|---|
| **他アプリを終了する** | Zwift・Rouvy・TrainerRoad 等が繋がっていると接続できません。BLE トレーナーは**同時に1台としか繋がらない**のが普通です。スマホのアプリも終了してください |
| **トレーナーを起こす** | 電源を入れ、**ペダルを数回転させる**。多くのトレーナーは動かさないとスリープしていて、Bluetooth の一覧に出てきません |
| **PC の Bluetooth を ON に** | Windows：設定 → Bluetooth とデバイス<br>Mac：システム設定 → Bluetooth |
| **Mac は Chrome に権限を** | システム設定 → プライバシーとセキュリティ → **Bluetooth** → **Google Chrome** を ON |

### 3-2. 接続する

1. 走行画面の右側 **「スマートトレーナーに接続」** をクリック
2. Chrome のデバイス選択ダイアログが開く
3. 一覧からトレーナーを選び **「ペア設定」** をクリック
4. 「○○ に接続しました」と出れば成功

接続後、デバイス欄に次のどちらかが表示されます。

- **「接続済み（勾配連動に対応）」** → 坂道でペダルが重くなります
- **「接続済み（勾配連動には非対応）」** → 走行はできますが負荷は変わりません

### 3-3. 走る

**「走行開始」** を押してペダルを回してください。実際の速度で景色が進みます。

### 3-4. 繋がらないときは

| 症状 | 原因と対処 |
|---|---|
| ダイアログに何も出ない | トレーナーがスリープ中 → ペダルを回してから再試行。他アプリが掴んでいる → 全部終了 |
| 「Web Bluetooth に非対応」と出る | Safari・Firefox・iOS を使っている → **PC/Mac の Chrome** で開く |
| 繋がるが数値が 0 のまま | ペダルを回してください。それでもダメなら機種が FTMS 非対応の可能性（後述） |
| 走行中に切れる | 電波干渉。トレーナーと PC を近づける。USB3.0 機器（2.4GHz に干渉）を離す |

**FTMS 非対応のトレーナーについて**：古い機種やメーカー独自プロトコルのみの機種は
この一覧に出てきません。お使いの機種名を教えていただければ、対応方法を検討します。

## STEP 4 — API キーを取って 3D 映像を出す

ここまでは 2D 表示です。フォトリアルな 3D 映像を出すには Google の API キーが要ります。

> **費用について**：クレジットカードの登録が必要ですが、3D タイルは月1,000セッションが
> 無料枠で、**1回のライド＝1セッション**です。毎日乗っても無料枠に収まります。
> それでも念のため、4-4 の上限設定を必ず行ってください。

### 4-1. プロジェクトを作り、課金を有効にする

1. **https://console.cloud.google.com/** を開く（Google アカウントでログイン）
2. 画面上部のプロジェクト選択 → **新しいプロジェクト** → 名前を入れて **作成**
   （例: `virtual-cycling`）
3. 左メニュー **お支払い** → **請求先アカウントをリンク**
   → 無い場合は作成（クレジットカード登録が必要）

### 4-2. 4つの API を有効化する

左メニュー **API とサービス** → **ライブラリ** で、以下を1つずつ検索して
**「有効にする」** を押します。

| API 名 | 用途 |
|---|---|
| **Maps JavaScript API** | 3D 表示・ストリートビュー |
| **Map Tiles API** | フォトリアル 3D タイル（映像の本体） |
| **Routes API** | 地点指定でのルート生成 |
| **Elevation API** | 標高・勾配 |

**4つとも必要です。**1つでも抜けると 3D が出ない、勾配が効かない等が起きます。

### 4-3. キーを作る

1. **API とサービス** → **認証情報**
2. 上部 **＋ 認証情報を作成** → **API キー**
3. 表示された `AIza...` で始まる文字列を**コピー**（後で使います）

### 4-4. キーに制限をかける（⚠️ 必ずやってください）

キーはブラウザから見える状態になるため、制限しないと第三者に使われて
**高額請求が発生しえます。**

作成直後のダイアログ、または認証情報一覧からキー名をクリックして編集画面へ。

**① アプリケーションの制限**

- **ウェブサイト** を選択
- **「ウェブサイトの制限」→ 追加** で以下を入力：
  ```
  https://kuzu-noha.github.io/github.io/*
  ```
- STEP 5（手元の PC で動かす）も使うなら、これも追加：
  ```
  http://localhost:8000/*
  ```

**② API の制限**

- **キーを制限** を選択
- プルダウンから 4-2 で有効化した **4つの API だけ**にチェック

→ **保存**

**③ 1日の上限を決める**

**API とサービス** → 各 API を選択 → **割り当てとシステム上限** タブ
→ 1日あたりのリクエスト数に上限を設定します。

目安（毎日1回30分乗る想定の2〜3倍）：

| API | 1日の上限の目安 |
|---|---|
| Map Tiles API | 50 |
| Maps JavaScript API | 100 |
| Routes API | 50 |
| Elevation API | 50 |

**④ 予算アラート**

左メニュー **お支払い** → **予算とアラート** → **予算を作成**
→ 金額を 1,000円 などに設定し、50% / 90% / 100% で通知が来るようにします。

これが**最後の安全網**です。設定してください。

### 4-5. アプリにキーを入れる

1. アプリを開く：`https://kuzu-noha.github.io/github.io/app/`
2. 右上 **「設定」**
3. API キーの欄にコピーした `AIza...` を貼り付けて **「保存」**
4. **「✅ Google Maps 読み込み済み（3D 映像が使えます）」** と出れば成功

キーは**この端末のブラウザにのみ保存**され、リポジトリにもサーバーにも送信されません。
別の PC で使うときは、その PC でも同じ手順が必要です。

### 4-6. 3D で走る

ルートを選び直して走行を開始すると、フォトリアルな 3D 映像になります。

- **「見回す（ストリートビュー）」** ボタンで、その場の実写を確認できます
- 1km ごとに自動でストリートビューが数秒表示されます
- 設定画面の **カメラ距離 / カメラ俯角** で視点を調整できます
  （地上に近づけるほど 3D タイルの粗さが目立つので、初期値の 50m / 74度 を推奨）

### 4-7. うまくいかないときは

| 症状 | 対処 |
|---|---|
| 「Google Maps の読み込みに失敗」 | 4-2 の API が有効化されていない。特に **Map Tiles API** の抜けが多いです |
| 3D にならず 2D のまま | 同上。または課金が有効になっていない |
| 画面が真っ暗 | その地域が 3D タイル非対応。プリセットの「ゴールデンゲートブリッジ」で試すと切り分けできます |
| `RefererNotAllowedMapError` | 4-4 ① のウェブサイト制限が URL と一致していない。末尾の `/*` を確認 |
| 勾配が常に 0.0% | Elevation API が未有効。または GPX に標高が無い |

エラーの詳細は **F12 → Console** に出ます。内容を教えていただければ切り分けます。

## STEP 5 —（任意）手元の PC で動かす

GitHub Pages を使わず、ローカルで動かすこともできます。
コードを触りながら試したいときはこちらが速いです。

```bash
git clone https://github.com/KUZU-NOHA/github.io.git
cd github.io
git checkout claude/google-maps-virtual-cycling-txcloc

python3 -m http.server 8000
```

ブラウザで **http://localhost:8000/app/** を開きます。

> **なぜ `file://` で開いてはいけないか**
> Web Bluetooth は HTTPS か `localhost` でしか動きません（secure context 要件）。
> また ES Modules も `file://` では読めません。必ず上記のようにサーバー経由で開いてください。
> `localhost` は例外的に HTTP のままで Bluetooth が使えます。

API キーを使う場合は、4-4 ① のウェブサイト制限に `http://localhost:8000/*` を追加してください。

### テストを走らせる

```bash
node --test test/unit.mjs   # 単体テスト 43件（ブラウザ不要）
node test/e2e.mjs           # E2E テスト（要 npm install playwright）
```

## 補足 — iPhone で使いたい場合

iOS の Safari も iOS 版 Chrome も Web Bluetooth に対応していないため、
**そのままでは Bluetooth が使えません**（画面の表示や記録の閲覧はできます）。

使う場合は App Store の **WebBLE**（有料・数百円）というブラウザをインストールし、
その中で `https://kuzu-noha.github.io/github.io/app/` を開いてください。
WebBLE は iOS の CoreBluetooth を Web Bluetooth API に橋渡しする専用ブラウザです。

ただし WebBLE は Web Bluetooth API の一部しか実装していないため、
**実機で確認するまで動くとは断言できません**。まず PC/Mac で動かして、
そのあと WebBLE を試すのが確実です。
